# CodeNest 技术文档（初稿）

> 本文档在 Zread 生成的解读基础上重写：逐条核对了引用出处，补上了工具读不出的设计动机与踩坑记录，删掉了「本项目采用先进架构」这类与代码无关的套话。

## 一、这个项目解决了什么问题

CodeNest 是一个纯静态的个人技术博客，没有后端、没有构建步骤，双击 `index.html` 就能跑。它要解决的不是「怎么把文章发到网上」——那件事 Hexo、Hugo 早就做完了——而是三个维护期的具体麻烦：

**第一，样式改不动。** 最初颜色、圆角、阴影是散在各个选择器里写死的，想换一套配色要全局搜索替换几十处，改完还要担心漏了某个 hover 态。现在 `css/style.css` 第 2 行起的 `:root` 和第 17 行的 `[data-theme="dark"]` 各自声明同一组 13 个自定义属性（`--bg`、`--surface`、`--accent`、`--radius`、`--shadow` 等），下面所有规则只引用变量、不写字面值。换主题变成了改一个块。

**第二，主题记不住。** 早期版本每次刷新都回到亮色，因为主题只存在内存里。现在 `js/main.js` 第 2–8 行先读 `localStorage` 的 `theme`，读不到再问 `matchMedia("(prefers-color-scheme: dark)")`，两者都没有才落到亮色；点击切换时（第 10–19 行）先算反色、再写 `data-theme` 属性、最后回写 `localStorage`，刷新后能接上。

**第三，交互逻辑没法验证。** 这是我认为最值得说的一个动机。`nav.classList.toggle("open")` 这种代码，除了用肉眼点一遍，没办法在 CI 里断言「点两次应该回到关闭」。于是我把三块交互等价抽成 `core.py` 里的 `ThemeManager`、`MenuState`、`CardAnimator`，用 `tests/test_core.py` 的 32 条用例覆盖边界：非法主题值要抛 `ValueError`（`test_toggle_theme_invalid_raises`）、未注册的卡片要抛 `KeyError`（`test_on_intersect_unregistered_card_raises`）、`tags` 不是列表要抛 `TypeError`（`test_tags_not_list_raises`）。

## 二、怎么实现的

**主题切换。** `ThemeManager.get_initial_theme()`（core.py 第 40 行）的优先级是「已存值 > 系统偏好 > 亮色」，且已存值必须落在 `VALID_THEMES` 里才采纳——这样即使用户手动把 `localStorage` 改成 `"blue"` 也不会崩，只会退回默认。`toggle_theme()`（第 53 行）先 `_validate_theme` 再查 `OPPOSITE_THEME` 映射表，而不是写 `if dark then light else dark`，好处是将来加第三套主题只需要扩表。

**移动端菜单。** `MenuState`（第 82 行）是个只有 `is_open` 一个字段的状态机，`toggle` / `close` / `open` 三个方法分别对应 JS 里的 `classList.toggle` / `remove` / `add`。JS 那边在 `main.js` 第 34–36 行还给每个导航链接挂了点击后关闭菜单的行为——这个细节很容易漏，漏了的结果是窄屏下点了链接、页面跳走了、菜单却还挂在那儿。

**卡片入场动画。** `CardAnimator.register_card()`（第 125 行）按卡片序号算错峰延迟 `index * 0.08`，生成 `transition: opacity 0.5s 0.16s, transform 0.5s 0.16s`；`on_intersect()`（第 140 行）只在 `is_intersecting` 为真时把 `opacity` 推回 `1`、`transform` 推回 `translateY(0)`，否则什么都不做。对应的 JS 在 `main.js` 第 40–57 行，用 `IntersectionObserver` 加 `threshold: 0.1`，卡片滚进视口 10% 就触发。

**数据校验。** `validate_post()`（第 171 行）检查 5 个必填字段（`title`/`date`/`category`/`excerpt`/`tags`）、`tags` 必须是 list、`title` 必须非空字符串，分别抛 `ValueError` 和 `TypeError`。配合 `filter_posts_by_category()` 和 `filter_posts_by_tag()`，这三者本是为「从 JSON 动态渲染文章列表」准备的接口，目前还没接到页面上。

## 三、亮点凭什么成立

我不太想用「架构清晰」这种谁都能说的话。可验证的亮点只有两条：

1. **行为可对照。** `core.py` 每个方法上方都贴了它对应的 JS 原文（见第 42–47、55–58、126–131、142–146 行的 docstring）。这意味着一旦有人只改了 JS 忘了改 Python，或者反过来，代码评审时把两段放在一起看就能发现分叉。同时这也让 Python 版不是「另写一份」，而是「同一份逻辑的第二个可执行表达」。
2. **错误有明确边界。** 32 条用例里有 7 条专门测异常路径（非法主题、未注册卡片、缺字段、`tags` 类型错、`title` 为空、入参不是 dict）。测异常比测正常路径更能说明「这个模块到底约定成什么样」。

## 四、已知问题（Zread 读不出、我自己踩过的）

- `index.html` 第 14、31 行和 `about.html`、`post.html` 第 13 行的图片用的是 `file:///D:/niufu/glogo.png` 这种本机绝对路径。换台机器打开就是裂图，推到仓库里别人 clone 下来也看不见。这是最初图省事留下的，正确做法是把图片放进 `assets/` 用相对路径引用。
- 全站没有 `prefers-reduced-motion` 降级。卡片动画和 hover 过渡对前庭功能敏感的用户不友好，应当加一条媒体查询把过渡时长归零。
- 文章列表是手写的静态 HTML 卡片，`core.py` 里的筛选函数还没接到 UI 上，所以「分类」「标签」两个锚点目前只是占位。
