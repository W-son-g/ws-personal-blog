从零设计一个高并发消息队列

精选 2026-09-10 · 阅读约 12 分钟

一、为什么需要消息队列

消息队列（Message Queue）是分布式系统中的核心基础设施，主要解决三大问题：解耦、异步、削峰。当用户请求量瞬时暴增时，MQ 可以作为缓冲层保护下游服务。

二、核心架构

一个典型的 MQ 由以下模块组成：

  • Producer：生产者，负责发送消息
  • Broker：消息代理，存储与转发
  • Consumer：消费者，订阅并处理消息

三、存储引擎设计

为了支撑百万级 TPS，我们采用 顺序写 + 零拷贝 的设计。消息以追加方式写入磁盘文件，通过 offset 索引定位。

// 简化的追加写逻辑
func (s *Store) Append(msg []byte) (offset int64, err error) {
    s.mu.Lock()
    defer s.mu.Unlock()

    n, err := s.file.Write(msg)
    if err != nil {
        return 0, err
    }
    offset = s.offset
    s.offset += int64(n)
    s.index.Put(offset, n)
    return offset, nil
}

💡 顺序写的性能接近内存写，这是 Kafka、RocketMQ 等主流 MQ 的共同选择。

四、消费模型

支持两种消费语义：At-Least-Once 和 Exactly-Once。前者实现简单，后者需要配合事务或幂等机制。

五、总结

设计一个生产级 MQ 涉及存储、网络、一致性等多个领域。本文只覆盖了核心骨架，后续将深入探讨主从同步、位点提交与故障恢复。
